## 2026-11-19 (3) — 사선·패닝 영상의 각도, 다이버 직접 지정, 속도
- **각도 계산 재작성** — 몸통축·입수각을 2D `atan2`(0~180°, 왼쪽을 향하면 24°가 156°) 대신 3D 수평면 기준(0~90°)으로. 무릎·몸통은 세트 구간 중앙값
- **세트 자세 = 이륙 직전 마지막 준비 자세** (몸통>55°·다리<40°). 한 번 일어섰다 다시 준비하는 영상(v4)에서 추적 시작 프레임을 세트로 잡던 문제
- **이륙 시점 = 입수 전 마지막으로 다리 각 < 40°였던 다음 프레임** — 비행 중 다리 각이 50° 기준을 오르내려 비행 구간이 1~2프레임으로 잘리던 문제
- **축척 = 다이버 몸 기준** (화면 분절 / 3D 분절). 블록 0.70 m 보정선 기본값(24%·80%)은 사선 영상에서 엉터리였음. 선을 직접 움직이면 블록 기준
- **카메라 이동 보정** — 다이버를 가린 배경 블록 매칭으로 패닝 측정, 궤적에서 뺌
- **비행 궤적 = 골반 중점 + 이상점 제거 재적합** — 분절 질량 무게중심은 팔·손끝 보정에 흔들리고, 입수 물보라 프레임이 튐
- **신뢰도 게이트** — 역산 중력 9.81±3.5, 비행 프레임 7개 이상일 때만 이륙각·수평속도를 점수에 반영. 아니면 "참고값"
- **측정 조건 안내** — 사선 촬영 정도, 카메라 이동, 참고값 사유를 점수 카드에 표시
- **정렬 편차 = 비행 구간 중앙값** (최댓값은 작은 인물에서 잡음 하나가 결과가 됨)
- **다이버 직접 지정** — 재생바 '다이버 지정' → 현재 장면 사람들 번호 박스 → 탭한 사람으로 재추적
- **속도** — 1차 스캔을 씨앗 구간(앞 42%, 14장)으로 한정해 스캔 추론 55% 절감. 분석 시간·추적 프레임 수 표시
- 정렬: `analyzeVideo` 후처리를 `afterExtract`로 공용화, 남은 `res` 참조 오류 수정
- `tools/e2e.py --replay`(추적 없이 분석만 수 초), `--pick-at/--pick-xy`(다이버 지정 실제 클릭 시험)

## 2026-11-19 (2) — 다이버 추적 재설계, 영상 인식 실패 안내
- **다이버 추적 재설계** — 프레임마다 "가장 그럴듯한 사람"을 고르던 방식은 옆에 선 사람·다음 선수·배경 물체로 갈아탔다 (4개 영상 실측).
  1차 스캔(32장 × 전체+타일)으로 모든 후보 → 숙인 자세로 오래 머문 사람을 다이버 씨앗으로 → 예측 위치 주변만 조밀 추적
  (거리·크기 게이트, 몸통이 선 사람 거부) → 비행 후 놓치거나 1.5초 공백이면 입수로 보고 종료
- 너무 꽉 자른 크롭에서 모델이 6배 크기 가짜 골격을 내는 문제 → 최소 패딩 2.2배
- 놓친 프레임은 예측 위치 근처 타일로 고해상도 재탐색
- 국면 힌트: 입수 직전 마지막 비행 구간 시작 = 이륙, 추적 종료 = 입수 (고정 보정선보다 우선)
- 추적률을 준비~입수 구간 기준으로 표시
- **영상 인식 실패 안내** — 파일에서 HEVC(hvc1/hev1) 감지, 메타데이터 실패·검은 프레임이면 원인과 해결책(Safari/Chrome, 아이폰 '높은 호환성', H.264 변환) 표시
- `tools/e2e.py` 추적 결과 덤프(JSON), `tools/check_js.sh` 문법 검사
